# Day 111: Platform Resilience & Security Center

## Overview

The **Platform Resilience & Security Center** acts as the trusted governance, recovery, and protection layer of DevOpsEase. This subsystem ensures platform state consistency, provides an immutable audit trail, and enables fast, safe disaster recovery via a staged execution model.

## Architecture Highlights

### 1. Unified Security & Governance (Explainability)
- **Deprecated `SecurityLog`:** Removed fragmented audit logs in favor of the core `PlatformEventBus`.
- **New Security Domains:** Categorizes security events accurately into `AUTH`, `SECRETS`, `INFRASTRUCTURE`, `RECOVERY`, `AUDIT`, and `COMPLIANCE`.
- **Explainable by Design:** All security and compliance events inherit the exact same AI-ready Explainability schema used for Runtime Observability, exposing `actor`, `trigger`, `decision`, and `reason` without duplicate tables.
- **Persistent INFO Logs:** Updated `platformHealth.service.js` to persist `INFO` level events specifically for Security domains, ensuring a full audit history is retained while ignoring routine platform noise.

### 2. Self-Describing Backup Manifests
- **Model:** `BackupManifest` directly tracks `platformVersion`, `schemaVersion`, `checksum`, `storageMetadata`, and `collectionMetadata` (including exact document counts).
- **JSON Payload:** The backup artifact stored via `StorageService` is a raw JSON payload containing the entire platform metadata.
- **Retention Tiers:** Moves beyond simple expiration timestamps to structured policies: `daily`, `weekly`, `monthly`, and `pinned`.

### 3. Decoupled Restore Lifecycle (Staged Execution)
Restore operations avoid direct mutations, separating planning from execution:
1. **Planning (`restorePlanner.js`):** Validates checksums and schema versions. Generates a diff plan (`inserts`, `updates`, `deletes`) across all critical collections without touching the database.
2. **Pre-Backup:** Automatically creates a `pinned` fallback backup before applying destructive changes.
3. **Maintenance Mode:** Temporarily pauses `PlatformScheduler` during execution to guarantee atomicity and prevent concurrent writes.
4. **Execution (`restoreExecutor.js`):** Applies the calculated plan atomically per collection.
5. **Verification:** Recalculates database document counts and strictly asserts they match the `BackupManifest`. Rolls back (via failure logging) if consistency cannot be proven.

### 4. Integration
- Natively registered inside `PlatformScheduler` (`backup:daily`, `backup:retention`).
- Backups use the exact same pluggable `StorageService` used by Artifacts and Build Logs.
- Exposed via a new UI `SecurityCenterPage` and `BackupsPage` grouped under the unified Admin Panel.

This architecture ensures DevOpsEase is not just observable and self-healing, but inherently resilient and fully auditable from the core to the UI.
