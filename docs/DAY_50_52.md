# 📅 Day 50–52 — Docker Compose Projects (Governed Implementation)

Multi-service project deployment using Docker Compose YAML, fully integrated with the existing ContainerService, image governance, storage tracking, and multi-tenant isolation — without touching the docker-compose CLI.

---

## 🎯 Objective

- Allow users to deploy multi-service applications by submitting a Compose YAML.
- Enforce security rules at the YAML validation layer (no privileged containers, no host networking, no absolute volume mounts).
- Integrate Compose-created containers with the existing ownership, resource, image tracking, and audit systems.
- Register registry images (`nginx:alpine`, etc.) in the Image model with storage accounting.
- Fix container display names so the internal namespace is never leaked in the UI.

---

## 🏗 Backend

### `project.model.js` *(new)*
Mongoose schema for projects: `userId`, `name`, `namespace`, `composeYaml`, `status`, `services[]`, `networks[]`, `volumes[]`. Unique compound index on `{ userId, name }`.

### `composeValidation.service.js` *(new)*
YAML validation using `js-yaml`. Blocks:
- `privileged: true`
- `network_mode: host`
- `pid: host` / `ipc: host`
- `cap_add`, `devices`
- Absolute host volume mounts (`/foo` or `C:\...`)
- More than 10 services
- Non-image (build-from-source) services

### `project.service.js` *(new)*
Core orchestration service:
- **Create**: validates YAML → checks quota (max 5 projects) → creates isolated Docker bridge network → delegates container creation to `containerActions.createContainer()` → registers ownership, resource, and image → saves Project document → triggers image reconciliation. Full rollback on partial failure.
- **Stop / Start**: delegates to `stopContainer()` / `startContainer()` (includes action history, cache invalidation, exec cleanup).
- **Delete**: removes containers via `removeContainer()`, releases ownership, marks resources deleted, removes Docker network, triggers reconciliation.

### `imageRegistration.service.js` *(new)*
`ensureImageRegistered({ userId, imageName })`:
- Inspects image via Docker API to extract Id, size, and layer count.
- **New image**: creates Image record with `pulledFrom: 'REGISTRY'` and increments `user.storageUsedMB`.
- **Same image already registered**: updates `ACTIVE` status, increments `pullCount` — **no double-counting**.
- **Tag updated to new digest**: adjusts storage delta.
- Called per service after container creation in `project.service.js`. The service's internal dedup (by `dockerImageId`) prevents double-counting when two compose services share an image.

### `project.controller.js` + `project.routes.js` *(new)*
Six routes under `/projects` (all behind `authMiddleware`):
- `POST /projects` — create
- `GET /projects` — list (excludes `composeYaml`)
- `GET /projects/:id` — detail
- `POST /projects/:id/start`
- `POST /projects/:id/stop`
- `DELETE /projects/:id`

### `containerActions.js` *(modified)*
Extended `createContainer()` to accept optional compose-specific parameters: `networkMode`, `labels`, `volumes`, `command`, `restartPolicy`. All parameters are optional — existing callers are unaffected.

### `image.js` (Model) *(modified)*
- `buildId` made optional (`required: true` → `default: null`) so registry images can be stored without a build reference.
- Added unique index `{ userId: 1, dockerImageId: 1 }` to enforce one record per image digest per user.

### `index.js` *(modified)*
Mounted `projectRoutes` at `/projects`.

## 🖥️ Frontend

### `api/index.ts` *(modified)*
Added `Project` + `ProjectService` TypeScript interfaces and a `projectApi` object with `create`, `list`, `getById`, `start`, `stop`, `delete` methods.

### `useProjects.ts` *(new)*
React Query hooks: `useProjects`, `useProject`, `useCreateProject`, `useStartProject`, `useStopProject`, `useDeleteProject` — all with cache invalidation.

### `ProjectsPage.tsx` *(new)*
Lists projects with status badges. Inline create form with a YAML textarea, validation error list, and deploy button.

### `ProjectDetailPage.tsx` *(new)*
Shows project namespace, service list (name / image / container ID), YAML viewer, start/stop/delete actions with a confirmation modal.

### `ResourceNav.tsx` *(modified)*
Added **Projects** tab with `FolderKanban` icon.

### `App.tsx` *(modified)*
Protected routes added for `/projects` and `/projects/:projectId`.

### `formatters.ts` *(modified)*
`formatContainerName` is now compose-aware: detects the `project_<userId>_<slug>_<service>` pattern and returns a clean `<project> / <service>` display string. Applied in `ContainerCard.tsx` and `ContainerDetails.tsx`.

---

## ✅ Outcome

> Users can deploy multi-service applications from a Compose YAML through the DevOpsEase dashboard. All containers, images, and storage are tracked identically to manually-created containers — no separate codepath, no audit gaps, no double-counting. The UI hides internal namespacing and shows clean project/service names.
