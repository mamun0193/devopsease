# Day 101 — Intelligent Application Gateway & Architecture Polish 🌐

## Overview
Day 101 is a landmark sprint that transforms DevOpsEase from a deployment dashboard into a **true Platform-as-a-Service (PaaS)**. We built the **Intelligent Application Gateway** — a production-grade reverse proxy layer that gives every deployed application a clean, stable URL and eliminates raw port exposure entirely.

On top of the core gateway, we completed an **Architecture Refinement Sprint** to future-proof the system for custom domains, HTTPS, multi-environment deployments, rate limiting, and additional providers — all without modifying the gateway core. We then performed a **Legacy Code Cleanup** to remove dead code and centralize all hardcoded URLs.

---

## 🌟 Flagship: Intelligent Application Gateway

### The Problem
Previously, deployed applications were accessed via random host ports:
```
http://localhost:4012   ← random, forgettable, exposed
http://localhost:9823   ← another random port
```

### The Solution
Every application now gets a clean, human-friendly gateway URL:
```
http://localhost:5173/apps/ecop
http://localhost:5173/apps/blog
http://localhost:5173/apps/api
```

Internally, DevOpsEase resolves the application, verifies permissions, checks health, and transparently proxies the request to the correct container. No container ports are ever exposed directly to the user.

### Core Gateway Architecture
- **Router Service** — Parses `/apps/:slug/*` URLs, extracts slug and subPath, validates slug format
- **Resolver Service** — Maps slug → Application → active Deployment → RuntimeEndpoint with TTL caching
- **Proxy Service** — HTTP and WebSocket reverse proxying via `http-proxy`, with path rewriting and error handling
- **Gateway Middleware** — Pluggable pipeline with context injection, tracing, metrics, and auth
- **Gateway Service** — Main orchestrator: parse → resolve → auth → proxy
- **Endpoint Resolver Registry** — Provider-agnostic registry pattern (Docker today, K8s/ECS tomorrow)
- **Docker Endpoint Resolver** — Resolves Docker container endpoints with health checking

## 🏗️ Architecture Refinement Sprint (8 Refinements)

### 1. Gateway Request Context
Every proxied request now carries a structured `GatewayRequestContext`:
- **Request Identity**: `requestId`, `correlationId` (generated or from headers)
- **User Identity**: `userId`, `isAuthenticated` (from JWT)
- **Application Context**: `applicationId`, `slug`, `visibility`
- **Deployment Context**: `deploymentId`, `provider`, `runtime`
- **Timing**: `resolved`, `proxied`, `completed` lifecycle markers
- Provides `toLogContext()` for structured logging and `toProxyHeaders()` for downstream services

### 2. GATEWAY_BASE_URL — Decoupled Gateway URLs
The gateway never hardcodes `localhost:5173`. A `GATEWAY_BASE_URL` environment variable controls all URL generation:
- **Development**: `http://localhost:5173/apps/ecop`
- **Production**: `https://apps.devopsease.com/ecop`

The `defaultDomain` field on each Application stores the canonical gateway URL, derived from this config.

### 3. Protocol-Agnostic RuntimeEndpoint
The endpoint resolver returns a rich `RuntimeEndpoint` descriptor instead of flat fields:
```js
{
  endpoint:     'http://127.0.0.1:4012',
  provider:     'docker',
  protocol:     'http',
  healthy:      true,
  version:      'v1.2.3',
  capabilities: ['http', 'ws'],
  metadata:     { containerId, containerName, port, replicaCount },
  deploymentId: '...',
  applicationId: '...',
}
```

### 4. Enriched Docker Runtime Metadata
The Docker resolver now returns container-specific metadata: `containerId`, `containerName`, `containerIds`, `port`, and `replicaCount` — all surfaced in the dashboard.

### 5. Extensible Middleware Pipeline
The gateway follows the Open/Closed principle with three extension phases:
```js
registerGatewayMiddleware('rateLimiter', 'pre-resolve',  rateLimiterFn);
registerGatewayMiddleware('analytics',   'post-resolve', analyticsFn);
registerGatewayMiddleware('headerInject', 'pre-proxy',    headerFn);
```
No core gateway code needs modification to add new middleware.

### 6. SPA Compatibility Extension Point
The proxy service documents a ready-to-activate History API fallback for React, Vue, Angular, and Svelte single-page applications.

### 7. Enhanced Observability
New metrics tracked by the gateway:
| Metric | Type |
|---|---|
| `activeWsConnections` | Gauge |
| `totalWsConnections` | Counter |
| `wsBytesTransferred` | Counter |
| `topApplications` | Top-10 by request count |

### 8. Reserved Extension Points
The architecture naturally supports future features without modification:

| Future Feature | Extension Point |
|---|---|
| Blue/Green, Canary | `environments[]` + traffic weights |
| Custom Domains | `customDomains[]` + domain-based routing |
| Rate Limiting | Pre-resolve middleware |
| SSL Termination | Protocol-aware proxy + HTTPS resolver |
| Load Balancing | Multi-endpoint RuntimeEndpoint + strategy |
| A/B Testing | Post-resolve middleware |
| Analytics | Post-resolve extension |

## 🧹 Legacy Code Cleanup & URL Centralization

### Direct Port Links Removed
- `DeploymentsPage.tsx` — `http://localhost:${port}` → `/apps/${slug}`
- `RecentDeploymentsTable.tsx` — Same migration

### Centralized Configuration (`config.ts`)
Created a single source of truth for all environment-dependent URLs:
```ts
export const API_BASE_URL  = import.meta.env.VITE_API_BASE_URL  || 'http://localhost:3497';
export const WS_BASE_URL   = import.meta.env.VITE_WS_BASE_URL   || 'ws://localhost:3497';
export const GATEWAY_BASE_URL = import.meta.env.VITE_GATEWAY_BASE_URL || '';
```

**10 files migrated** to import from `config.ts` instead of hardcoding `localhost:3497`:
- `api/index.ts`, `repo.api.ts`, `LoginPage.tsx`
- `useLogStream.ts`, `useDeploymentSocket.ts`, `useContainerEvents.ts`
- `useAlertSocket.ts`, `useBuildSocket.ts`, `usePipelineSocket.ts`
- `ContainerTerminal.tsx`

### Backend: Deployment → Application Slug Mapping
The deployment list API now returns `applicationId` and `applicationSlug` for each deployment, enabling gateway-aware links without extra API calls.
