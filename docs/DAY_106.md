# Day 106 - Release Orchestration Platform

## Objective
Build a robust, scalable release orchestration system to manage complex deployments, control traffic routing, and provide deep explainability into platform decisions. 

## Backend Architecture

### 1. Release Manifests (Immutability)
We introduced the `ReleaseManifest` model as an **immutable snapshot** of the exact artifacts needed to run an application. This acts as the single source of truth for a release, binding together:
- `applicationId`
- `configSnapshotId` (Environment Variables, Secrets)
- `buildManifestId` (The exact build configuration)
- `imageId` (The produced container image)

### 2. Release State Machine
The `Release` model tracks the lifecycle of a deployment and maps one-to-many to `ReleaseTarget` models (allowing for multi-region or multi-cluster scale). The state machine flows through:
- `Draft`
- `Prepared`
- `Deploying`
- `Validating`
- `Promoting`
- `Active`
- `Archived` / `RolledBack`

### 3. Traffic Management
We implemented a traffic routing subsystem capable of handling advanced rollout strategies (Canary, Blue/Green, A/B Testing).
- **TrafficPolicy**: Defines the rules and criteria (e.g. 10% traffic to v2, 90% to v1).
- **RoutingTable**: The compiled, executable instructions that the gateway uses to actually forward packets.

### 4. Explainability 
DevOpsEase is an educational platform; therefore, "black box" decisions are unacceptable. We replaced free-form explanation logs with structured `ExplainabilityRecord` objects. Every automated decision (e.g., auto-rollback, traffic shift) logs:
- `decision` (What happened?)
- `trigger` (What caused it?)
- `reason` (Why did the intelligence engine decide this?)
- `actor` (System vs. User)

## Frontend Dashboard

We extended the dashboard to provide full visibility and control over releases.

### 1. Releases Overview (`ReleasesPage.tsx`)
- Added a high-level view of all releases with metrics for Active, Draft, and Rolled Back releases.
- Included an interactive, filterable data table.

### 2. Release Details (`ReleaseDetailsPage.tsx`)
- **Traffic Overview Widget**: Visualizes current traffic splits between active releases.
- **Release Lifecycle Timeline**: Tracks the state machine progression.
- **Tabbed Inspector**:
  - **Manifest Viewer**: Inspect the raw JSON of the immutable release manifest.
  - **Routing Path**: Understand exactly how the gateway is routing traffic to targets.
  - **Telemetry / Explainability**: Read the structured explainability logs for the release.
- **Action Dialogs**: Support for Promoting a prepared release or Rolling back an active release.

### 3. UI/UX Consistency (The "dds" Theme)
- Removed hardcoded raw tailwind classes (e.g. `bg-slate-900`) and fully integrated the new pages into the custom DevOpsEase design system.
- Implemented `bg-dds-bg`, `text-dds-text-primary`, and `.card` wrappers.
- Matched typography, borders, and hover transitions precisely to the standard `Pipelines` and `Deployments` tables for a cohesive, sleek user experience.
